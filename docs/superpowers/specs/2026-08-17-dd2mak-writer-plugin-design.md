# dd2mak Writer Plugin — 설계 스펙

작성일: 2026-08-17  
상태: 승인됨 (에이전트 자동화는 Phase 2로 설계, Phase 1 구현 범위에는 넣지 않음)

## 1. 한 줄 요약

기존 `dd2mak` 테마는 그대로 두고, **글 초안 → 검수 → 발행**만 담당하는 워드프레스 플러그인을 만든다. 작성자는 카테고리와 키워드로 AI 초안(약 2천자)을 만든 뒤 제출만 하고, 검수자가 수정·보완한 다음 발행하면 기존 사이트 메뉴에 글이 올라간다.

## 2. 범위

### 한다

- 플러그인 `dd2mak-writer` (테마 파일 수정 없음)
- 작성자 메뉴: 새 초안 작성, 내 글
- 검수자 메뉴: 검수 대기, 발행된 글, AI 설정
- AI 초안 생성: 카테고리 1개 + 키워드 → 약 2천자
- 제공자 선택: Anthropic / OpenAI / Gemini / Cursor
- 발행 시 기존 카테고리=`post` 카테고리로 저장 → 테마 메뉴에 자동 노출

### 하지 않는다

- 테마 소스 수정, 프론트 사이트 신규 구축
- 전용 CPT (기본 `post` 사용)
- 작성자에게 반려·재작성 루프 (보완은 검수자가 직접)
- 일자리 공고 CPT 작성 화면
- 모델명 자유 입력, 사용량 대시보드, 다중 언어
- Phase 1에서 REST API, Cursor 에이전트, 과정 오케스트레이터를 구현하는 것 (테스트 완료 후 Phase 2)

## 3. 사용자와 권한

| 역할 | 워드프레스 역할 | 할 수 있는 일 |
|---|---|---|
| 작성자 | 기여자(Contributor) | 초안 생성·편집, 검수 제출, 내 글 조회. 발행 불가 |
| 검수자 | 편집자(Editor) 또는 관리자 | 검수 대기 글 수정·보완, 출처/검수일 입력, 발행, AI 설정 |

플러그인은 `publish_posts`가 없는 계정에게 발행 버튼을 보여주지 않는다. 기여자가 기본 글 화면에서 발행하는 경로도 막지 않고, **이 플러그인 메뉴 밖 글쓰기는 안내만** 한다. 이 플러그인 화면의 제출은 항상 `pending`으로 저장한다.

## 4. 메뉴

작성자:

- 정보글
  - 새 초안 작성
  - 내 글

검수자:

- 정보글 검수
  - 검수 대기
  - 발행된 글
  - AI 설정

작성자가 제출하면 그 글은 작성자 **내 글**에서 “검수 대기”로 보이고, 검수자 **검수 대기** 목록에 나타난다.

## 5. 화면

### 5.1 새 초안 작성 (작성자)

입력:

- 카테고리: 아래 6개만 선택 (미분류 제외, 하위 카테고리 없음)
  - 건강관리 / 복지혜택 / 일자리·재취업 / 연금·재무 / 여가·배움 / 디지털 생활
- 키워드: 한 줄 텍스트
- 버튼: 초안 만들기

동작:

1. 카테고리·키워드가 비어 있으면 생성하지 않고 안내한다.
2. 선택된 제공자로 초안을 받아 제목 필드와 본문 에디터에 채운다.
3. 작성자가 본문을 고칠 수 있다.
4. **검수 제출** → `post_status=pending`, 카테고리 지정, 작성자=현재 사용자. 성공 시 내 글로 이동.

임시 저장은 **작성 중 저장** 버튼으로 `draft` 저장. 제목이 비어 있으면 저장하지 않는다.

### 5.2 내 글 (작성자)

열: 제목, 카테고리, 상태(작성 중 / 검수 대기 / 발행됨), 날짜.  
작성 중(`draft`)만 다시 열어 제출할 수 있다. 검수 대기·발행됨은 읽기 전용.

### 5.3 검수 대기 (검수자)

`pending` 글 목록. 열어 본문 수정, 아래 검수 정보 입력 후 **발행** (`publish`).

검수 정보 (테마 상세에 나오게 같은 메타 키로 저장):

- 정보 출처 (`_dd2mak_source`)
- 최종 검수일 (`_dd2mak_reviewed_at`)
- 주의 문구 (`_dd2mak_caution`) — 비워도 발행 가능
- AI 초안 여부 (`_dd2mak_ai_draft`) — 생성에 성공한 글은 1, 검수자가 원할 때만 해제

테마가 다른 키를 쓰면 구현 시 테마 소스에 맞춰 키만 바꾼다. 키를 못 찾으면 위 키를 쓰고 테마 표시는 나중에 맞춘다.

### 5.4 발행된 글 (검수자)

`publish`이면서 이 플러그인으로 만든 글(`_dd2mak_writer=1`)만 목록. 다시 열어 수정·업데이트 가능.

### 5.5 AI 설정 (검수자만)

- 사용할 제공자: Anthropic / OpenAI / Gemini / Cursor (라디오 또는 셀렉트, 하나만 활성)
- 제공자별 API 키 (비밀번호 필드). 저장 후 화면에는 마지막 4자만 보여 준다.
- 제공자를 바꿔도 이미 저장한 다른 제공자 키는 유지한다.
- **연결 확인** 버튼: 키로 최소 호출(모델 목록 또는 짧은 ping). 실패 시 이유 문구.

기본 모델 (설정에 모델 입력란 없음):

| 제공자 | 모델 |
|---|---|
| Anthropic | `claude-sonnet-4-20250514` |
| OpenAI | `gpt-4o` |
| Gemini | `gemini-2.0-flash` |
| Cursor | 사용하지 않음 (아래 제약) |

`wp-config.php`의 `DD2MAK_ANTHROPIC_API_KEY`는 **폴백**이다. 설정 화면에 Anthropic 키가 있으면 설정을 쓰고, 없을 때만 상수를 쓴다. OpenAI/Gemini/Cursor는 설정 화면 키만 쓴다.

## 6. AI 초안 규칙

시스템 프롬프트에 고정:

- 독자: 50~70대. 쉬운 말. 가벼운 재치(비유·한마디 정도). 말장난·영어 말장난 금지.
- 분량: 본문 한글 기준 약 2,000자 (공백 포함, HTML 제외). 목표 1,800~2,200자. 프롬프트에 명시하고, 받은 뒤 글자 수를 화면에 보여 준다. 미달·초과여도 강제 재생성하지 않는다.
- 제목: 질문형이 아니라 행동형 한 줄.
- 본문: H2 소제목 3~6개. 디지털 생활이면 3~5단계.
- 복지·의료·연금액 등 수치는 지어내지 않는다. 확인이 필요하면 본문에 `[확인 필요]`를 남긴다.
- 출력: 제목 한 줄, 이어서 HTML 또는 마크다운 본문. 플러그인이 제목/본문으로 분리해 에디터에 넣는다.

생성 실패(키 없음, 한도, 네트워크): 에디터는 비우지 않고 직전 내용을 유지하며, 상단에 오류만 보여 준다. 키 없이 사람이 직접 써도 제출할 수 있다.

### Cursor 제공자 제약

Cursor 공식 API는 클라우드 에이전트/SDK용이며, **카페24 PHP에서 호출하는 채팅 완성 API가 없다.**  
설정 목록에는 Cursor를 넣는다. 선택 시:

- 초안 만들기는 막고, “Cursor는 이 서버에서 초안 생성에 쓸 수 없습니다. Anthropic, OpenAI, Gemini 중 하나를 선택하세요.”를 보여 준다.
- 키 저장은 허용한다 (나중에 쓸 수 있게).

OpenAI 호환 프록시 URL 입력은 Phase 1에 넣지 않는다. Cursor 키는 Phase 2에서 워드프레스 밖 에이전트 런타임(Cursor SDK / Cloud Agents)용으로 쓸 수 있게 저장만 해 둔다.

## 7. 데이터

- 글 유형: `post`
- 플러그인 작성 표시: 첫 저장부터 `_dd2mak_writer = 1`
- 상태: `draft` → `pending` → `publish`
- 카테고리는 테마가 만들어 둔 6개 슬러그를 이름으로 찾아 연결한다. 없으면 같은 이름으로 생성한다 (테마 활성화 전이어도 제출은 되게).

슬러그 (테마와 맞출 값, 구현 시 테마 `functions.php`가 있으면 그 값을 우선):

| 이름 | 슬러그 |
|---|---|
| 건강관리 | `health` |
| 복지혜택 | `welfare` |
| 일자리·재취업 | `jobs` |
| 연금·재무 | `finance` |
| 여가·배움 | `leisure` |
| 디지털 생활 | `digital` |

## 8. 기술 구조

카페24 워드프레스 플러그인. PHP, 관리자 화면만. 프론트엔드 라우트 없음.

```
wordpress-plugin/dd2mak-writer/
  dd2mak-writer.php     부트스트랩, 메뉴, 권한
  inc/process.php       과정 함수 (화면과 향후 에이전트가 동일 호출)
  inc/pages.php         작성·내글·검수·발행 화면 — process 함수만 호출
  inc/settings.php      AI 설정 저장/표시
  inc/ai.php            제공자별 HTTP 호출, 프롬프트
```

화면 핸들러에 발행·상태 변경 로직을 직접 넣지 않는다. 모든 상태 변경은 `inc/process.php`를 통한다. 각 과정이 끝나면 `do_action`을 한 번 호출해 Phase 2 에이전트가 붙을 자리를 남긴다.

- Phase 1 관리자 요청은 `admin-post.php`(또는 `admin-ajax.php`)와 nonce만 사용한다. REST는 Phase 2에서 같은 과정 함수 위에 얹는다.
- API 키는 `update_option`으로 저장. `autoload=false`. 로그·에러 메시지에 키를 넣지 않는다.
- 외부 HTTP는 WordPress `wp_remote_post`.

## 9. 오류 처리

| 상황 | 동작 |
|---|---|
| 제공자 미선택 또는 키 없음 | 초안 만들기 실패 안내. 수동 작성은 가능 |
| Cursor 선택 | 위 Cursor 제약 안내 |
| API 4xx/5xx | 제공자 메시지 요약. 본문 유지 |
| 카테고리 없음 | 제출 시 생성 후 연결 |
| 작성자가 pending/publish 글 수정 시도 | 거부, 내 글로 |

## 10. 성공 기준

1. 기여자 계정으로 로그인 → 정보글 메뉴만 보임. 카테고리+키워드로 초안 생성(키 설정된 제공자) → 검수 제출 → 상태가 검수 대기.
2. 편집자 계정으로 검수 대기에서 글 수정 후 발행 → 프론트에서 해당 카테고리 글이 보임.
3. 기여자는 발행 버튼이 없고, 발행된 글을 바꿀 수 없음.
4. AI 설정에서 제공자·키를 저장하고, 저장 후 키는 끝 4자만 보임.
5. 테마 zip/PHP를 이 플러그인이 수정하지 않음.
6. 초안 생성·저장·제출·검수 수정·발행이 각각 `inc/process.php`의 독립 함수이고, 화면은 그 함수만 호출한다.

## 11. 배포

`wordpress-plugin/dd2mak-writer.zip`을 만들어 워드프레스 `플러그인 > 새로 추가 > 업로드`로 설치한다. 기존 `dd2mak` 테마와 함께 쓴다.

## 12. Phase 2 — 과정별 에이전트 자동화 (테스트 완료 후)

Phase 1은 사람이 화면에서 과정을 돌린다. 테스트가 끝나면 **같은 과정 함수**를 에이전트가 하나씩 호출하도록 붙인다. 에이전트가 워드프레스 글을 직접 건드리지 않는다.

### 12.1 에이전트 = 과정 1:1

| 에이전트 | 과정 함수 | 입력 | 출력 | 권한 |
|---|---|---|---|---|
| DraftAgent | `dd2mak_generate_draft` | 카테고리 슬러그, 키워드, 작성자 ID | `post_id`, 제목, 본문 (`draft`) | 작성자 |
| SaveAgent | `dd2mak_save_draft` | `post_id`, 제목, 본문, 카테고리 | `post_id` (`draft`) | 작성자, 본인 글만 |
| SubmitAgent | `dd2mak_submit_for_review` | `post_id` | `pending` | 작성자, 본인 `draft`만 |
| ReviewAgent | `dd2mak_update_review` | `post_id`, 제목, 본문, 출처/검수일/주의 | `pending` 유지 | 검수자 |
| PublishAgent | `dd2mak_publish_post` | `post_id` | `publish` | 검수자, `pending`만 |

작성자가 에디터에서 고치는 단계는 Phase 1에서는 사람이다. Phase 2에서 DraftAgent가 생성 직후 SaveAgent까지 이어서 호출할 수 있다.

### 12.2 오케스트레이션

기본 파이프라인:

1. DraftAgent (초안 생성)
2. SubmitAgent (검수 대기)
3. ReviewAgent (사실 확인, `[확인 필요]` 보완, 문장 다듬기) — **검수자가 결과 확인**
4. PublishAgent (발행) — **사람 승인 후에만**. 완전 자동 발행은 옵션 스위치가 켜졌을 때만.

에이전트는 서로 글을 넘기지 않고, 오케스트레이터가 `post_id`만 넘긴다.

### 12.3 Phase 2에서 추가할 인터페이스 (지금은 구현하지 않음)

REST (`dd2mak/v1`), 애플리케이션 패스워드 또는 전용 토큰:

- `POST /drafts` → DraftAgent
- `POST /posts/{id}/save` → SaveAgent
- `POST /posts/{id}/submit` → SubmitAgent
- `POST /posts/{id}/review` → ReviewAgent
- `POST /posts/{id}/publish` → PublishAgent

Cursor SDK / Cloud Agents는 이 REST를 호출하는 **워커**다. PHP 안의 Anthropic/OpenAI/Gemini 초안 생성과 역할이 다르다.

### 12.4 Phase 1이 남겨야 할 훅

과정 함수 성공 시 한 번씩:

- `dd2mak_after_generate_draft`
- `dd2mak_after_save_draft`
- `dd2mak_after_submit_for_review`
- `dd2mak_after_update_review`
- `dd2mak_after_publish_post`

인자: `$post_id`. Phase 1에서는 리스너를 등록하지 않는다.
